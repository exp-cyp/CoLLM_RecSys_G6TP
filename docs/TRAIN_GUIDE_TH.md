# การฝึกและประเมินผล

## เริ่มการทดลอง

ติดตั้ง environment และเตรียม MovieLens-1M กับ Qwen2-0.5B ตาม [README](../README.md)
ก่อนเริ่มการทดลอง

1. ดับเบิลคลิก **START_TRAIN.cmd** ที่หน้าแรกของโปรเจกต์
2. รอข้อความ **พร้อมแล้ว** หลังตรวจข้อมูล โมเดล อุปกรณ์ และสถานะ Git
3. ตรวจค่าการทดลองที่แสดง แล้วกด **Train**

ปุ่ม Train ใช้ assets ในเครื่อง ไม่มีการติดตั้งหรือดาวน์โหลดระหว่างฝึก
Source ต้องอยู่ใน commit ที่ตรงกับ upstream เพื่อบันทึกเวอร์ชันที่ใช้ทดลอง

## การตั้งค่า

- โมเดลฐาน: Qwen2-0.5B, revision ที่ pin ไว้
- ข้อมูล train / validation / test: 4,096 / 512 / 1,024
- MF embeddings: 64 มิติ
- Batch 4, gradient accumulation 2
- Stage 1 และ Stage 2: 512 optimizer steps ต่อส่วน
- ใช้ Intel Arc 140T ผ่าน XPU; MF ใช้ CPU
- จำกัดเวลา 6 ชั่วโมงต่อขั้น แยกจากเวลารวมทั้ง pipeline

ค่าฝึกอยู่ใน [`configs/local.yaml`](../configs/local.yaml) แต่ละรอบมีชื่อเฉพาะ
และสำเนา config ของตนเอง ผลรอบเก่าไม่ถูกเขียนทับ

## ลำดับการทำงาน

โปรแกรมทำตามลำดับ:

1. ฝึก MF และเลือก checkpoint ด้วย validation
2. ฝึก LoRA จากข้อความ เป็น baseline แบบ TALLRec
3. ฝึก MLP เชื่อม MF กับ Qwen เป็น CoLLM-MF
4. ประเมิน test ชุดเดียวกันทั้งสามโมเดล
5. บันทึก metrics, predictions และรายงานพร้อมกราฟการฝึก

หน้าต่างแสดงขั้นตอนและ log ระหว่างรัน ปุ่ม **หยุดอย่างปลอดภัย** จะรอจบการคำนวณย่อย
และบันทึกสถานะก่อนหยุด

เมื่อรอบก่อนหยุด โปรแกรมนำขั้นที่เสร็จและผ่านการตรวจสอบกลับมาใช้ได้
ส่วนขั้นที่ยังไม่เสร็จจะเริ่มใหม่ ไม่ใช่การทำต่อจาก optimizer step เดิม
การใช้ checkpoint ต้องผ่านการตรวจความเข้ากันได้ของโค้ด โมเดล ข้อมูล และค่าฝึก

## ผลลัพธ์

กด **เปิดผลลัพธ์** เพื่อเปิดรายงาน HTML ของรอบนั้น ประกอบด้วย:

- ตาราง AUC ของ MF / TALLRec / CoLLM-MF และส่วนต่างที่วัดได้จริง
- กราฟเปรียบเทียบและกราฟ loss/validation ระหว่างฝึก
- เวลา จำนวน steps ที่ทำจริง และสถานะของแต่ละขั้น
- `predictions.csv`, `ranking_example.csv`, config และรายงานละเอียด

| โฟลเดอร์ | ข้อมูล |
|---|---|
| `outputs/<run>/` | MF, LoRA และ mapper checkpoints |
| `results/<run>/` | metrics, predictions, กราฟ และรายงาน HTML |
| `.cache/jobs/<run>/` | config, log รวม และสถานะการรัน |

สถานะ `time_limit` หมายถึงมีขั้นตอนที่หยุดตามเพดานเวลาก่อนครบแผน
เลือก checkpoints และค่าฝึกด้วย validation แล้วใช้ test ประเมินผลของโมเดลที่เลือก
ผลจาก `configs/smoke.yaml` ใช้ตรวจ pipeline และแสดงแยกจากผลทดลอง
